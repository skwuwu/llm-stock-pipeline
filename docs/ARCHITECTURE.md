# 아키텍처 — 작동 방식과 그 근거

이 문서는 **무엇을 하는가**보다 **왜 그렇게 했는가**에 무게를 둔다.
각 결정에는 그것을 강제한 실측이 붙어 있다. 숫자가 없는 주장은 적지 않았다.

> 초기 설계서는 [`DESIGN.md`](DESIGN.md)에 있으나 등급 체계(tier A/B/C) 시절
> 문서라 §7이 낡았다. 검증 레이어의 현재 모습은 이 문서 §5를 볼 것.

---

## 0. 전체 흐름

```
L0  인제스천      DART · KIND · FinanceDataReader          → data/raw/**  (불변)
L1  정규화        계정 매핑 · TTM 복원 · 성장률             → facts_financial
L2  파생지표      107개 지표 + 품질 플래그                   → metrics_{date}.parquet
L3  스크린        하드가드 → 적응형 게이트 → 랭킹            → survivors.parquet
L4  엔리치먼트    사업보고서 섹션 발췌 · 세그먼트 추출        → pack.json
L5  LLM 태깅      Haiku → 조건부 Sonnet 승급        💰      → tags_{date}.json
L7  검증          V1 인용 · V2 섹터 · V3 비중                → verdicts.parquet
L7' 촉매          공시 → 촉매·역촉매 + 신뢰도 6체크          → catalysts.parquet
L8  측정          골든셋 대비 오분류율                        → golden_metrics.json
L9  출력          다이제스트                                  → digest.md
```

L6(클러스터링)은 비워 뒀다 — 테마가 47개로 고정돼 있어 군집화가 할 일이 없다.

## 1. PIT — 세 개의 시간축

모든 fact는 세 날짜를 갖는다.

| 축 | 뜻 | 쓰임 |
|---|---|---|
| `fiscal_end_date` | 회계기간 종료일 | 기간 비교 |
| `reported_at` | 공시일 (`rcept_no[:8]`) | 정정 순서 |
| `available_at` | 우리가 쓸 수 있게 된 날 | **모든 조회의 경계** |

`available_at = reported_at + 1일`이 기본이다. 장중/장마감 공시 구분이 없으므로
익영업일부터 쓸 수 있다고 본다 — 백테스트 보수성을 위한 선택이다.

**정정공시는 UPDATE 하지 않는다.** `revision_of`를 달아 append 한다. 그래야
"그때 알던 값"과 "지금 확정된 값"을 둘 다 질의할 수 있다. `fact_id`에
`source_doc_id`가 들어가 있어 정정본은 자동으로 새 행이 된다.

**raw는 불변이다.** `data/raw/dart/**`의 JSON은 절대 덮어쓰지 않는다.
파서 가정이 틀렸을 때 `renormalize`가 **API 호출 0회로** facts를 통째로
재생성한다. 실제로 이 설계가 여러 번 값을 했다 — 아래 §2의 계정 필드 규칙,
§7의 주식수 라벨 버그 모두 재수집 없이 고쳤다.

## 2. 정규화 — 한국 재무제표의 함정

### TTM 복원

한국은 분기 **누적**으로 보고한다. 3분기 손익은 9개월 누적이다.

```
m == 12 :  TTM = FY(y)
m <  12 :  TTM = FY(y-1) − CUM(y-1, m) + CUM(y, m)
```

구성요소가 하나라도 없으면 **값을 만들지 않고** `ttm_reason`을 남긴다.
빈칸을 0으로 메우면 PER이 조용히 틀린다.

### '누적'이 담기는 필드가 재무제표마다 다르다

이건 문서에 안 나와 있어 실데이터로 확정했다.

```
손익계산서(IS/CIS) 분기
  thstrm_amount     = 당분기 3개월      ← 누적 아님
  thstrm_add_amount = 당기 누적          ← 이걸 써야 한다
  (삼성전자 3Q24: thstrm 9.78조 / add 26.05조)

현금흐름표(CF) 분기 — IS 와 의미가 정반대다
  thstrm_amount   = 당기 누적
  frmtrm_q_amount = 전년 동기 '누적'
  add 계열 필드는 아예 없다
  (기아 2025: 1Q 3.01 → 반기 5.35 → 3Q 8.63 → FY 9.05조 단조증가)
```

IS의 `frmtrm_q_amount`(3개월)를 CF의 것(누적)과 같게 취급하면 분기 PER이
조용히 3~4배 어긋난다. 출처 필드를 `amount_field` 컬럼에 남기므로 규칙이
또 바뀌어도 `renormalize`로 고칠 수 있다.

### 성장률 — TTM 대 TTM은 불가능하다

직전연도 TTM을 만들려면 2년 전 같은 분기 누적(1Q24)이 필요한데 **실측 3종목**
뿐이다. 그래서 두 가지만 만든다:

- `*_growth_fy` — FY25 vs FY24. 유효율 95.8%, 안정적이나 최대 7개월 묵는다
- `*_growth_q` — 1Q26 vs 1Q25. 신선하나 단일분기 노이즈

**기저가 0 이하면 성장률을 만들지 않는다.** −10억 → +100억은 −1100%라는
무의미한 수가 된다. 대신 `turnaround`로 표시한다 — 흑자전환은 성장 스크린이
가장 놓치면 안 되는 유형인데 NaN으로만 두면 조용히 빠진다.

**증가율과 함께 증가액(`*_delta_*`)도 낸다.** 비율만 있으면 기저가 작을 때
폭주한다. 실측: 실적 서프라이즈 상위가 전부 그런 종목이었다(해성디에스 2,995%,
펄어비스 2,597%). 촉매 C3는 증가율이 아니라 **증가액/시총**을 쓴다.

## 3. 파생지표와 품질 플래그

107개 컬럼. 핵심은 규약이다:

```
PER = 시총(보통주+우선주) / 지배주주 순이익 TTM
PBR = 시총(보통주+우선주) / 지배주주지분
```

분모에 총자본을 쓰면 비지배지분만큼 저평가로 보이고, 분자에 보통주 시총만
쓰면 우선주 있는 회사가 저평가로 보인다. 둘 다 흔한 오류다.

### 데이터가 틀렸을 때 잡는 장치

주가 소스가 하나뿐이라 교차검증 수단이 제한적이다. 셋을 쓴다:

**① 시총 × 자본 × 매출 삼각 검증** — PBR만으로도 PSR만으로도 못 가린다.
저마진 유통·상사는 PSR이 정상적으로 낮고(서원 0.028), 자산주는 PBR이 낮을 수
있다. **둘 다 무너지면 시총 자체가 틀린 것이다.** 매출·자본은 DART에서 오므로
주가와 완전히 독립이다.

**② 배당 역산 주가** — `DPS ÷ 회사 보고 배당수익률` = 회사가 쓴 기준가.
우리 종가와 5배 이상 벌어지면 하나가 틀렸다. 실측: 대한제분 DPS 4,000원 /
3.0% = 153,846원인데 저장된 종가가 11,510원이었다.

**③ 물리적 불가능** — `MAX_PLAUSIBLE_MARKET_CAP` 2,000조, PBR 200 초과.
실측으로 LS에코에너지가 시총 1,395조(주식수 30.6조 주)로 걸렸다.

### 결측을 0으로 메우지 않는다

이 파이프라인 전체를 관통하는 규칙이다.

- 유동비율 NaN을 "100% 이상"으로 처리하면 금융업이 조용히 면제된다
- DART 금액 `'-'`를 0으로 읽으면 "미기재"와 "0원"이 같아진다
- 세그먼트 미공시를 0%로 읽으면 "안 밝혔다"가 "안 한다"가 된다

## 4. L3 스크린 — 적응형 게이트

### 하드가드는 절대 튜닝하지 않는다

자본잠식·거래정지·데이터 오류 종목이 목표 개수를 맞추려다 통과하면
파이프라인의 존재 이유가 사라진다. 가드 컬럼이 없으면 **조용히 건너뛰지 않고
실패시킨다** — 가드가 도는 줄 알고 안 도는 상태가 가장 위험하다.

가드가 0건을 배제해도 **제거하지 않고 0이라는 사실을 보이게** 둔다.
실측: `is_preferred`는 KIND 목록이 법인 단위라 0건이지만, 소스가 종목 단위로
바뀌면 즉시 필요해진다.

### 적응형 tightness

정량 필터만 스칼라 `t ∈ [0,1]`로 loose↔tight를 보간하고, 목표 종목 수에
이분탐색으로 수렴한다. 각 필터가 `t`에 단조여야 성립하므로 `assert_monotone`이
매 실행 검사한다.

**밴드는 고정한다.** GARP의 PER 10~25는 종목 수 노브가 아니라 "정상
밸류에이션"의 정의다. 보간 대상으로 두면 이분탐색이 목표를 맞추려고 밴드를
넓힌다 — 실측으로 6.0~29.0까지 벌어져 스크린의 정체성이 사라졌다.

### 히스테리시스는 '직전 리밸런스' 기준

'직전 실행'을 쓰면 일별로 돌릴 때 기준이 매일 어제로 밀려, 잦은 교체를
막으려던 장치가 정반대로 작동한다 — 바스켓이 서서히 표류한다.
그래서 **스캔(일별)과 리밸런스(주/월)를 분리**한다. 스캔은 진입·이탈 후보만
보고하고 바스켓을 건드리지 않는다.

### 위험은 개수가 아니라 범주로 센다

`low_roic`과 `low_roe`는 같은 사실을 두 번 말하는 것이다. 개수로 세면
상관관계 높은 지표를 여러 개 넣을수록 자동으로 위험해 보인다.
`risk_groups` = **서로 다른 종류의 문제가 몇 개인가** (현금창출/재무구조/
수익성/배당지속/지배구조).

이 축은 **검증(테마가 맞나)과 완전히 독립**이다. 섞으면 "테마 분류 품질"과
"싸 보이는 이유가 재무에 있나"가 한 숫자로 뭉개진다.

## 5. L7 검증 — 이 파이프라인의 정체성

### 폐기 사유는 둘뿐이다

```
unknown_theme           사전에 없는 테마 = 환각
hallucinated_citation   인용문이 원문 어디에도 없다
```

나머지는 전부 **표시**다. `status ∈ {verified, rejected}`.

### 등급(A/B/C)을 없앤 이유

폐기 전 마지막 형태는 이랬다:

- A와 B를 가르는 유일한 기준이 **LLM 자기신고 `confidence >= 0.75`** 였다
- `share_overclaim`(LLM 주장 vs 실측 괴리)이 C로 내리는 하드 플래그였다
- 그 결과 "이 종목은 B다"가 무엇을 뜻하는지 말할 수 없었다

실측으로 재실행 시 등급 일치율이 **84%**였고 CJ대한통운이 A↔C를 왕복했다.
모델이 매긴 소수점이 등급을 정하는 건 검증이라 부르기 어렵다.

지금은 두 사실만 낸다:

```
status          원문 인용으로 뒷받침되는가
share_evidence  confirmed / below_floor / not_found / unverified / unavailable / not_claimed
```

**비중 수치는 강등 근거로만 쓰고 숫자 그대로 리포트에 싣는다.** 38%인지
88%인지는 사람이 봐야 판단할 수 있는 정보다.

### V3 — 무엇을 유지하고 무엇을 버렸나

| 검사 | 입력 | 처리 |
|---|---|---|
| `role_downgraded_by_actual` | **실측 세그먼트** vs 택소노미 상수 | **역할 강등 유지** |
| `share_claim_gap` | **LLM 주장** vs 실측 | 표시만 |

전자는 LLM이 끼지 않고 `LABELING.md` R1이 쓰는 하한과 같은 규칙이라 남겼다.
이걸 없애면 택소노미가 자기 하한을 스스로 강제하지 않게 되는데, 골든셋은
그 하한을 적용하므로 **우리가 일부러 끈 규칙을 위반했다고 파이프라인을 벌하게**
된다.

### 한 테마가 여러 세그먼트에 걸칠 수 있다

LLM은 세그먼트 하나당 배정 하나를 내므로, 한 테마가 두 세그먼트에 걸치면
배정이 둘로 쪼개진다. 그대로 판정하면 각각 하한에 미달해 **둘 다** 강등된다.

실측: JYP는 음반 31.4% / 매니지먼트 68.6%로 나뉘어 **합계 100%인데도**
양쪽 다 core→adjacent로 내려갔다. 지금은 `merge_assignments`가
`(ticker, theme_id)`로 묶어 세그먼트를 합산한 뒤 한 번만 판정한다.

## 6. 촉매 — 왜 지금인가

테마와 근본적으로 다르다:

```
테마   상태. "화천기공은 공작기계 회사다"       → 시효 없음
촉매   사건. "7월에 자사주 430억 취득 결정했다"  → 반드시 만료된다
```

스키마에 시효가 없으면 6개월 전 뉴스가 오늘의 촉매로 계속 뜬다.

### 추출 세 경로 — 전부 LLM 없이

| 경로 | 촉매 | 방법 | 성공률 |
|---|---|---|---|
| 구조화 API | C1·X1 | `tsstkAqDecsn`·`piicDecsn`·`cvbdIsDecsn` JSON | 54/61, 42/81 |
| 문서 정규식 | C2 | 거래소공시 서식 고정 → `매출액 대비(%)` 라벨 | 330/342 (96%) |
| 자체 계산 | C3 | `op_delta_q` / 시총 | — |

C3를 파싱하지 않는 이유는 둘이다. 대상이 3,270건이라 문서 수집이 비싸고,
**같은 수치를 두 경로로 만들면 어긋날 때 어느 쪽이 맞는지 판정할 근거가 없다.**

### 신뢰도 = 정수

```
grounded        인용이 원문에 있다
not_amended     [기재정정] 후속이 없다
not_expired     expires_at >= as_of
material        magnitude >= 임계
no_reversal     반대 극성 촉매가 더 최근에 없다
numbers_agree   우리 지표와 방향이 맞다
────────────────────────────────────
0 ~ 6           전부 데이터 조회 → 재현된다
```

`material`은 **버리는 기준이 아니라 체크다.** 시총 0.5% 자사주도 일어난
사실이다 — 조용히 버리면 "작았다"와 "없었다"가 같아진다.
**버리는 것은 크기를 아예 모르는 경우뿐**이고, 그건 순위를 못 매겨서지
작아서가 아니다.

### 역촉매를 같이, 그리고 먼저

실측(19일): 주요사항보고 535건 중 **222건(41%)이 유상증자·CB**였다.
촉매만 찾는 시스템은 가장 흔한 신호를 통째로 놓치고 낙관 편향을 갖는다.
다이제스트에서 `## 역촉매`가 `## 촉매`보다 **위에** 있다 — 나쁜 소식이
스크롤 아래에 있으면 안 읽힌다.

## 7. LLM 계층

### 캐스케이드

```
Stage 0   키워드 + 섹터로 후보 테마 6개 압축        무료
Stage 1   Haiku 4.5                              temperature=0
Stage 2   confidence < 0.75 이면 Sonnet 5 승급     temperature 미지원
```

승급률 85~92%. **Sonnet 5는 `temperature`를 받지 않는다**(400 deprecated).
그래서 대부분의 호출을 온도로 고정할 수 없고, 이것이 재현성 한계의 직접 원인이다.

### 캐시

`cache_key = (model, system_fingerprint, pack_hash, candidates, temperature)`

- `system_fingerprint`는 **프롬프트 내용의 해시**다. `taxonomy['version']` 같은
  수기 문자열에 걸면 정의를 고치고 버전 올리는 걸 잊었을 때 재실행이 조용히
  옛 결과를 돌려준다 — 실제로 겪었다(제외 조항을 추가했는데 62종목 결과가
  한 건도 안 바뀜)
- `temperature`도 키에 들어간다. 안 넣으면 온도를 0으로 내려도 캐시가
  옛 결과를 돌려준다
- `pack_hash`가 **주가와 무관**하다. 그래서 일별 시세 갱신에 LLM 비용이 0원이다
  (실측 2,597/2,598 종목이 날짜가 달라도 동일 해시)
- 캐시는 **스크린 간 공유**한다. 같은 종목이 두 스크린에 걸리면 두 번째는 무료

### 캐시가 재현성을 만들어 주지는 않는다

캐시 적중은 같은 답을 돌려주지만 그건 모델이 결정적이라서가 아니라 답을
적어뒀기 때문이다. 캐시가 빗나가는 순간(택소노미 수정, 신규 종목) 진짜
결정성이 필요해진다.

## 7.5 생존편향 — 없앨 수 없으면 재기라도

유니버스는 KIND 상장법인목록에서 온다. 그 목록은 **현재 상장사만** 준다.
폐지된 회사는 목록에서 사라지고 `security_master` 에도 없다.

과거 as_of 로 스크린을 돌리면 그때 상장돼 있다가 이후 폐지된 종목이 통째로
빠진다. 살아남은 것만 남으니 성과가 구조적으로 부풀려진다.

### 폐지 이력을 사실로 기록한다

FDR `KRX-DELISTING` 이 폐지일·사유를 준다(주권 2,093건, 1960~2026).

**사유 분류가 핵심이다.** 주주에게 무슨 일이 일어났는가로 가른다:

| outcome | 뜻 | 2020+ |
|---|---|---:|
| `merged` | 합병·완전자회사화. 대가를 받았다 | 120 |
| `voluntary` | 자진상폐. 대개 공개매수 프리미엄 | 12 |
| `dissolved` | 스팩 해산·존속기간 만료. 환급 | 86 |
| `failed` | 감사의견 거절·계속성 결여. 사실상 전손 | 177 |
| `other` | 분류 불가 | 9 |

**합병 소멸을 전손으로 처리하면 반대 방향으로 틀린다.** 2026년 사례를 보면
성격이 완전히 다르다 — 더존비즈온(지주회사 완전자회사화)과 스타코링크
(계속성 결여)를 같은 '폐지'로 묶으면 편향을 고치려다 새 편향을 만든다.

`other` 를 `failed` 로 밀어넣지 않는다. 모르는 것을 전손으로 세면 역시
반대로 틀린다. 대신 수를 보여주고 패턴을 늘리게 한다(48 → 9건으로 줄였고,
남은 9건은 전부 종류주식 폐지라 보통주 유니버스와 무관하다).

`ToSymbol`(승계 종목)은 404건 중 12건만 채워져 있어 쓸 수 없다 —
사유 텍스트로 판정한다.

### PIT 유니버스

`PitStore.listed_asof(as_of)` 가 두 갈래를 합친다:

```
alive   지금도 상장 중이고 그때 이미 상장돼 있던 종목
gone    그때는 상장 중이었으나 그 뒤에 폐지된 종목   ← 이게 빠져 있었다
```

### 크기를 보이게 한다

`survivorship_report(as_of)` 가 편향을 수치화한다. 실측:

```
2026-08-06   상장 2,759 / 폐지 0        → 편향 없음. 지금 상장된 것을 보는 게 맞다
2023-01-01   상장 2,552 / 폐지 216      → failed 101 · merged 66 · dissolved 37 …
```

`screen` 이 과거 as_of 에서 이 경고를 낸다. 폐지 이력이 **아예 없을 때도**
경고한다 — 편향을 측정조차 못 하는 상태를 조용히 넘기지 않는다.

### 완전 해결이 가능한가 — 실측으로 답했다

"과거 시점 백테스트까지 편향 없이" 하려면 넷이 필요하다. 각각 **실제로
되는지 찔러봤다**(추측이 아니라 측정이다):

| 필요한 것 | 결과 | 근거 |
|---|---|---|
| ① 그때 상장돼 있던 종목 | **해결됨** | `listed_asof()` |
| ② 폐지 종목 재무 | **받을 수 있다** | DART 3/5. 사업연도 기준 failed 17/18·merged 14/18 |
| ③ 폐지 종목 주가 | **받을 수 있다** | FDR 8/8. 정리매매 최종가까지 |
| ④ 관리종목 지정 이력 | **불가능** | 스냅샷 1개뿐 |

**②가 예상과 반대였다.** "실패 기업은 재무를 안 낸다"고 걱정했는데
`failed` 94% / `merged` 78% 로 오히려 합병 쪽이 낮다 — 합병 소멸법인은
마지막 사업보고서를 아예 안 내고 사라지기 때문이다. 이건 편향이 아니다.
합병은 재무보다 합병비율이 필요하고 그건 합병 공시에 있다.

**③의 값이 정확히 필요한 것이다.** 한송네오텍 11원·이브이파킹서비스 1원
(정리매매 최종가 = 사실상 전손) vs 제이시스메디칼 12,900원(공개매수가).
`outcome` 분류와 맞물려 실제 손익을 재현할 수 있다.

**④가 진짜 벽이다.** KIND 관리종목 페이지는 **현재 지정 목록만** 준다.
2023년에 지정됐다 2024년에 해제된 회사는 어디에도 기록이 없다. `admin_issue`
는 하드가드이므로, 과거 시점 스크린은 그때 관리종목이던 회사를 못 거른다 —
생존편향과 **반대 방향**의 오염이다. 소급할 방법이 없고, 오늘부터 매일
스냅샷을 쌓아야 관측된다.

### 그래서 범위를 현재 시점으로 정했다

②③을 채우면 대부분 해결되지만, 그건 **백테스터를 만들 때 할 일**이다.
지금 이 저장소에는 백테스트 모듈이 없고(초기 로드맵 M5, 미착수),
데이터만 채워도 쓸 코드가 없다.

현재 시점 스크리닝에는 이 편향이 **없다** — 실측 2026-08-06 폐지 0종목,
커버리지 99.5%. 지금 상장된 종목을 보는 것이 애초에 맞는 동작이다.

남긴 것은 **경고와 측정**이다. 과거 날짜로 돌리는 것을 막지는 않되,
`screen` 이 크기를 말하고 `survivorship` 이 수치를 낸다. 폐지 종목의
`corp_code` 는 이미 손에 있으므로(DART corpCode 3,981개 중 1,222개 미상장)
범위를 넓히기로 하면 그때 채우면 된다 — 이전에는 **누가 빠졌는지조차
몰랐다.**

## 8. 측정 — 무엇을 믿을 수 있나

### 골든셋

126종목(딥밸류 62 + 성장 64). 규칙은 [`LABELING.md`](../tests/golden/LABELING.md)에
6가지로 명문화돼 있다. 핵심은 **재현 가능하게** 만드는 것이지 정답을 보장하는
것이 아니다 — 사람이 검수할 때 어디를 뒤집어야 하는지 알 수 있게.

`confidence: certain | contested`로 판정이 갈릴 수 있는 라벨을 표시하고,
**certain-only 지표를 함께 보고**해 숫자가 그 라벨들에 얼마나 기대는지 드러낸다.

라벨은 **티커당 한 곳에만** 둔다. 두 파일에 있으면 어느 쪽이 정답인지 갈리고
수정이 한쪽에만 반영된다. 스크린은 여러 파일을 합쳐 자기 코호트를 덮는다.

### 채점은 코호트로 한정한다

합친 라벨을 그대로 채점하면 다른 스크린의 라벨이 전부 FN이 된다 —
실측으로 재현율이 80.3% → 27.2%로 무너졌다. 그건 분류 성능이 아니라
"이 스크린이 남의 코호트를 안 뽑았다"는 사실을 재는 것이다.

### 코호트 가드의 분모

위험한 방향은 **"태깅됐는데 라벨이 없는"** 쪽이다 — 그 종목들은 분모 밖으로
조용히 빠져 지표가 코호트의 일부만 잰다. 반대 방향(라벨은 있는데 이번에
안 걸린 종목)은 타당성을 해치지 않는다.

### 재현성

리포트가 **재현 가능한 행과 아닌 행을 구조적으로 분리**한다.

```
■ 기준 지표 — core 일치 96% (누적 n=48, 표본 2회). 재현율 ±4%p 보다 작은 차이는 잡음이다
   검증 전 (LLM 원본 core)     96.1%  80.3%   3.9%
     (certain 라벨만)         100.0%  88.2%   0.0%

■ 참고 — 검증 반영. 판정 일치 81% — 기준 지표보다 더 흔들린다
   검증 후 / 비중 실측 확인분만 / 플래그 0건만 …
```

**단일 실행으로 "100% 재현"이라 말하지 않는다.** 첫 표본이 24/24로 나와
그렇게 적었다가 두 번째 표본 22/24에 뒤집혔다. 그래서 표본을 누적하고,
테스트가 `core_agreement < 1.0`을 강제한다.

## 9. 되풀이되는 설계 규율

이 파이프라인에서 같은 원칙이 여러 층위에 반복해서 나타난다. 새 기능을 붙일
때 이것들을 어기고 있지 않은지 보면 된다.

**① 조용한 실패를 만들지 않는다.**
가드 컬럼이 없으면 예외. 부분 수집이면 예외. 커버리지 미달이면 비정상 종료.
공시 목록이 잘리면 예외 — 잘린 목록으로 촉매를 만들면 "그 종목은 공시가
없었다"는 잘못된 결론이 나온다.

**② 결측과 0을 구분한다.**
`'-'` ≠ 0원. 세그먼트 미공시 ≠ 매출 0%. 유동비율 NaN ≠ 통과.

**③ 버리지 말고 표시한다.**
만료 촉매는 부록 C로. 임계 미만 촉매는 `chk_material=False`로. 위험 종목은
본문에서 부록으로. **버리면 "없었다"와 "약했다"가 같아진다.**

**④ 통과가 아니라 실패를 쓴다.**
`5/6`만 보여주면 무엇이 빠졌는지 모른다. 규모 미달인 자사주와 정정공시가
붙은 수주는 같은 5/6이어도 성격이 전혀 다르다.

**⑤ LLM에게 판단이 아니라 추출을 시킨다.**
테마는 "무엇을 하는 회사인가", 촉매는 "공시에 뭐라고 적혀 있나".
`kind`·`magnitude`·`expires_at`·신뢰도는 전부 규칙과 데이터가 정한다.

**⑥ 측정할 수 없는 것은 넣지 않는다.**
"AI 수요 수혜"를 촉매로 허용하는 순간 대조할 원문이 사라지고 환각률 측정이
불가능해진다. 그러면 이 시스템은 그냥 또 하나의 LLM 리포트 생성기가 된다.

## 10. 이 설계가 잡아낸 실제 버그

문서화 목적: 같은 유형이 또 나올 때 알아보기 위해서다.

| 버그 | 증상 | 원인 유형 |
|---|---|---|
| rapidfuzz 미설치 | V1 퍼지매칭이 조용히 `False` → 환각률 5.1% | **조용한 실패** |
| `_safe_div(a, 100.0)` | 1행 Series 브로드캐스트 → `payout_ratio` 전부 NaN | 조용한 실패 |
| 주식수 라벨 | `se == "보통주"` 완전일치 → **230종목(8.9%)** 시총 결측 | 조용한 실패 |
| `pblntf_ty="A"` 하드코딩 | 촉매가 사는 B·I에 닿을 수 없었음 | 하드코딩 |
| `<style>` 미제거 | 거래소공시 2,210자 중 1,209자가 CSS → LLM 입력 오염 | 파싱 |
| C2 이중 나눗셈 | 이미 비율인데 매출로 또 나눔 → 전 건 0% | 단위 |
| C3 증가율 폭주 | 기저 1억 → 30억이 2,900% → 랭킹 오염 | 단위 |
| JYP 세그먼트 분할 | 31.4% + 68.6% = 100%인데 양쪽 다 강등 | 집계 |
| 골든셋 분모 | 합친 라벨 전체가 분모 → 재현율 80.3% → 27.2% | 집계 |
| 캐시 무효화 누락 | 택소노미 수정에도 62종목 결과 불변 | 캐시 키 |

**주식수 라벨 버그가 가장 위험한 유형이었다.** 배제 사유가
`below_min_market_cap_or_missing`(시총 미달)로 찍혀 **데이터 결손처럼 보이지
않았다.** 삼성전기·LG전자·한미반도체·셀트리온이 "작은 회사"로 분류돼 조용히
빠져 있었다.
