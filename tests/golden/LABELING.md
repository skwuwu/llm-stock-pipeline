# 골든셋 라벨링 규칙 v2 (2026-08-07)

라벨을 매기는 사람이 바뀌어도 같은 답이 나와야 한다. 규칙이 없으면 지표가
"이 데이터가 얼마나 정확한가"가 아니라 "그날 라벨러가 어떻게 느꼈나"를 잰다.

## 무엇을 라벨링하는가

**core(주력) 테마만** 담는다. adjacent/peripheral 은 사람끼리도 판정이 갈려
라벨 신뢰도가 낮고, tier A 후보는 어차피 core 뿐이다.

## 규칙

**R1. core = 매출 30% 이상 + 손익의 주된 동인.**
비중은 사업보고서 매출실적표의 수치를 우선한다. 인상이나 회사 이름이 아니라
숫자로 판정한다. 수치가 없으면 서술문의 명시적 비중, 그것도 없으면 R6.

**R2. 테마의 `inclusion`/`exclusion` 을 문자 그대로 적용한다.**
"비슷하니까" 로 넣지 않는다. exclusion 에 걸리면 아무리 비슷해도 아니다.
예: `media_content_ip` 는 광고대행을 제외한다 → 이노션은 여기 들어갈 수 없다.

**R3. `allowed_sectors` 와 `core_revenue_share_min` 을 확인한다.**
둘 중 하나라도 못 넘으면 core 가 아니다. 이건 취향이 아니라 사전의 규격이다.

**R4. 사전에 칸이 없으면 `[]` 로 둔다.**
가장 가까운 테마를 억지로 고르지 않는다. 빈 라벨은 실패가 아니라
**사전 공백의 기록**이다 — 그게 쌓여야 다음 사전 개편의 근거가 된다.

**R5. 복수 core 는 각 사업이 독립적으로 하한을 넘을 때만.**
예: 아이에스동서 = 건설 36% + 환경 39% → 둘 다 core.

**R6. 판정이 갈릴 수 있으면 `confidence: contested` 로 표시하고 이유를 note 에 쓴다.**
갈리는 유형은 대체로 셋이다:
- 테마 경계가 애매하다 (차량용 디스플레이 = 전장인가 디스플레이 부품인가)
- 사전 정의가 그 업종을 상정하지 않았다 (농기계, SMPS)
- 세그먼트 비중이 근소하다 (37% vs 54%)

`contested` 라벨은 지표에서 빼지 않는다. 다만 **certain-only 지표를 함께 보고**해서,
숫자가 판단이 갈리는 라벨에 얼마나 기대고 있는지를 드러낸다.

## 필드

```json
{"ticker": "000850", "name": "화천기공",
 "core": ["industrial_machinery"],
 "confidence": "certain",
 "note": "CNC선반·밀링 등 공작기계 84% (매출실적표)"}
```

- `core` — 테마 id 배열. 빈 배열이면 사전에 칸이 없다는 뜻.
- `confidence` — `certain` | `contested`. 기본값 `certain`.
- `note` — **왜 그렇게 판정했는지.** 근거 수치를 넣는다. contested 면 무엇이 갈리는지.
- `evidence_defect` — evidence pack 본문이 사업의 내용이 아닌 경우. LLM 오분류로
  셀 수 없으므로 별도 집계한다.

## 이 라벨의 지위

`labeled_by: assistant-bootstrap`. 사업보고서 본문과 매출실적표를 읽고 위 규칙으로
매긴 것이며 **사람 검수 전이다.** 규칙을 명문화한 목적은 정답을 보장하는 게 아니라
**재현 가능하게** 만드는 것이다 — 사람이 검수할 때 어디를 뒤집어야 하는지 알 수 있게.

## 개정 이력

- **v1 (2026-08-06)** — 62종목 최초 라벨. 단일 검수. 라벨 1건(토비스)이 틀린 것이
  나중에 매출실적표 대조로 드러났고, 그 1건으로 오분류율이 5.9%→2.9% 움직였다.
- **v2 (2026-08-07)** — 규칙 명문화 + 전건 재검수. 택소노미 7개 신설로
  `[]` 였던 18종목 중 16종목이 라벨을 갖게 됐다(코어 보유 44 → 60).
  분모가 늘어 라벨 1건의 지렛대가 줄었다. `confidence` 필드 도입.
